# SkyTwin Frontend Design System

This document outlines the practical, data-first design approach for the SkyTwin frontend, emphasizing operational clarity over purely aesthetic trends like glassmorphism.

## 1. Core Philosophy

- **Practicality First:** The UI must resemble a real spacecraft operator's console. Information density, legibility, and clear status indication take priority over decorative elements.
- **No Glassmorphism:** Solid, opaque backgrounds with clear borders to ensure contrast and readability in a dark theme environment. No blur filters or translucent frosted glass.
- **Strict Color Semantics:**
  - **Data Series:** Validated CVD-safe palette (Blue, Orange, Aqua) defined in `lib/colors.ts`.
  - **Status:** Reserved purely for state (Green/Nominal, Yellow/Warning, Red/Critical). Every status color must be accompanied by an icon or text label for accessibility.
- **Dark Theme:** High contrast dark mode by default to reduce eye strain during continuous monitoring.

## 2. Layout Structure

The application follows a persistent top bar and a two-tab main content area (`App.tsx`).

### Top Bar
- **Branding:** "SkyTwin" logo/title.
- **Global Status:** High-level system health indicator (Nominal/Warning/Critical).
- **Navigation:** Primary toggle between **Live Mode** and **Simulation Mode**.

### Tab 1: Live Mode (Monitoring & Telemetry)
*Focus: Immediate situational awareness and anomaly detection.*

- **Header / Overview:**
  - **Spacecraft Animation:** A simple, CSS or lightweight SVG animation of a spacecraft in orbit, providing a visual heartbeat of the live telemetry. It slowly rotates or pulses gently, indicating the system is actively receiving data.
- **Stat Tiles:** Key metrics (Power, Thermal, Orbital Position) displayed in distinct, solid, bordered cards with current values and trend indicators.
- **Demo Event Panel:** Controls to inject emulated real-world anomalies (e.g., fault injection). The "Send to spacecraft" button is intentionally disabled to emphasize read-only safety.
- **Telemetry vs. Twin Residuals:**
  - TimeCharts displaying real telemetry against the digital twin predictions.
  - Charts use Recharts 3 with clear eclipse shading and uncertainty bands.
  - **Chart-to-Table Toggle:** Every chart includes a toggle to switch to a raw data table for precise inspection.
- **Alerts Feed:** A chronological list of anomaly detections and limit breaches.

### Tab 2: Simulation Mode (What-If Engine)
*Focus: Sandboxed scenario planning and risk assessment.*

- **Scenario Builder (Left Panel):**
  - Controls to configure "what-if" scenarios from presets (e.g., adding perturbations).
- **Compare View (Main Area):**
  - Side-by-side or overlaid charts comparing the **Baseline** trajectory against the **Scenario** prediction.
- **Result View (Bottom/Right Panel):**
  - **Risk Banner:** Highlighting the outcome of the simulation (e.g., Critical Risk of Power Drain).
  - **Impact Chain:** A visual sequence of how the initial perturbation cascades through the system.
  - **Narrative:** Plain-English explanation and recommendations generated by the engine.

## 3. UI Components & Styling

- **Containers:** Solid backgrounds (e.g., very dark grey `#121212` or slate `#18181B`), 1px solid borders (`#27272A`) for separation.
- **Typography:** Monospace fonts (like `Fira Code` or `JetBrains Mono`) for all data values and tables to ensure numbers align vertically. A clean sans-serif (like `Inter` or `Roboto`) for UI labels and prose.
- **TimeCharts:**
  - Built with Recharts 3 (`components/TimeChart`).
  - Clear axes, unobtrusive grid lines.
  - **Eclipse Shading:** Distinct background shading during orbital eclipse periods.
- **Interactive Elements:**
  - Buttons and toggles should have clear hover states (slight brightness increase) and active states (inset shadow or border highlight) without relying on heavy animations.

## 4. The Spacecraft Animation (Live Dashboard)

The live dashboard features a lightweight animation to represent the active telemetry stream.
- **Implementation:** An SVG graphic of the spacecraft (e.g., main body and solar panels).
- **Animation:** Continuous slow rotation (using CSS `@keyframes` to rotate 360 degrees over 60-120 seconds) to simulate orbital motion, or a subtle "breathing" effect linked to the 30-second `tick_sim_s` update loop.
- **State Changes:** The animation can shift its tint based on the global health status (e.g., a subtle red glow or dashed outline if there's an anomaly), remaining functional and unobtrusive.
